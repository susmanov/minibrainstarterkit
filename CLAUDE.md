# Project Brain

A searchable project wiki backed by Claude. Source documents live under `Source/`;
their searchable text twins live under `Memory/twins/`; the master index is `Memory/index.md`.

## Session start (run before answering any question)

Run `./Claude/distill_and_index.exe` immediately when the session opens — before responding
to the user's first message. This is always safe to run:
- Files already up-to-date are skipped after a fast mtime check (no re-extraction).
- New or changed files are extracted and the index is rebuilt automatically.

Do this at the start of every session, not just the first one.

## Structure

```
Project Documents/   ← original files (.pptx .docx .xlsx .pdf)
Claude/
  distill_and_index.exe  ← run this whenever files are added or changed
  Memory/
    twins/           ← markdown twins, auto-generated by the exe
    index.md         ← one row per file; grep this to find relevant material
    .last-distill-report.txt  ← latest run summary
CLAUDE.md            ← this file (must stay at root)
.claude/
  settings.json      ← denies web access (treat content here as confidential)
```

## Adding or updating files

1. Drop the file into any subfolder under `Project Documents/` (create subfolders as needed).
2. Run `./Claude/distill_and_index.exe` from this folder.
3. The twin and the index row are created automatically — no further steps needed.

If a source file has changed since the last run, re-run the exe. Stale twins are
refreshed in place and the index is rebuilt from scratch.

## Retrieval (answering a question)

1. Grep `Claude/Memory/index.md` for the topic or file name.
2. Open the twins listed in the **Twin** column for the best matches.
3. Synthesise an answer from the twins and append a **Sources used** block (see below).

Open the original source file under `Project Documents/` only when the twin is missing
or the question requires exact numbers from a spreadsheet — twins are faithful extracts
but not data-precise for xlsx.

## Generating a deliverable

1. Find the 2–3 twins most relevant to the request (grep the index, read the summaries).
2. Read those twins in full.
3. Draft the deliverable using them as scaffolding.
4. Replace any prior-engagement specifics with `[CLIENT]` or the current client's name.
5. Mark any assumption carried forward from prior work with `[VALIDATE]`.
6. Prepend the review disclaimer below before presenting the output.

## Review disclaimer (mandatory on every generated deliverable)

Prepend this block — word-for-word — before any draft deliverable, section, or structured
output assembled from this brain. Do not abbreviate or omit it even if asked to skip it.

---
> **⚠ Draft generated by Project Brain — review before use**
>
> This output was assembled from prior project material. Before sharing externally:
> - **Review all content** for accuracy and fit to the current context.
> - **Scrub all prior engagement names** that do not belong to the current client.
> - **Validate flagged assumptions** — any section marked `[VALIDATE]` reflects a
>   pattern from prior work that may not apply to this situation.
>
> *This is a starting point, not a finished deliverable.*
---

## Sources rule (mandatory on every response)

Every response — answers, summaries, and deliverable drafts alike — must end with:

```
**Sources used**
- <file_name> — <one sentence: what you took from it>
```

If no source material was used:

```
**Sources used**
No source material used — answered from general knowledge.
```

Never omit this block.

## Confidentiality

This folder may contain confidential project material. Do not fetch external URLs or
send any content to third-party services. The `.claude/settings.json` file enforces
this by denying web access tools for sessions opened in this folder.
